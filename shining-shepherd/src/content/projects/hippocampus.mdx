## Memory without loading every conversation

An AI assistant needs past decisions, rules, and project context. Sending every old conversation into every new task wastes context and makes the useful details harder to find.

Hippocampus is the retrieval layer inside my [Agentic System](/projects/agentic-system). It keeps curated memory and the raw transcript archive in one SQLite database while treating them as separate sources with separate search paths.

## The retrieval pipeline

Every query runs through two retrievers. FTS5 with BM25 finds exact names, commands, phrases, and file references. sqlite vec performs exact cosine distance search to find related meaning when the query uses different language.

Each retriever contributes up to 30 candidates. Reciprocal rank fusion merges the two rankings with a constant of 60. Maximal marginal relevance then reduces near duplicates and keeps up to 10 diverse candidates. The final scoring step weighs relevance, importance, memory type, and freshness before returning five memories.

That sequence solves different failure modes. Lexical search protects precise identifiers. Semantic search recovers concepts. Rank fusion avoids trusting one score scale. Diversity selection prevents five versions of the same memory from occupying the result.

## Memory types behave differently

The curated store separates procedural, semantic, and episodic memory. A durable operating rule should remain useful longer than a temporary task update, so freshness uses exponential decay constants chosen by type.

Those constants are decay windows, not mathematical half lives. The distinction matters because the ranking formula should be described as it is implemented.

The raw Echo archive serves a different purpose. It keeps searchable transcript chunks for cases where the exact conversation matters. Archive search is explicit, so a large historical record does not flood normal memory retrieval.

## Technical boundaries

The database and ranking logic run locally in Python with SQLite, FTS5, and sqlite vec. Query embeddings can use a cloud service, so the search path is not fully offline.

Vector retrieval is exact distance search. This design does not claim an approximate index or unlimited scale. A further model based reranking stage exists as an optional dormant path and is not part of the normal result.

Retrieval can still miss an important memory or surface an outdated one. Stored source metadata makes inspection possible, and the agent can search the transcript archive when the curated result is insufficient.

## Why I built it

Hippocampus turns memory into an engineering subsystem with explicit stores, ranking stages, and limitations. I use it in daily work to recover project decisions without repeatedly explaining the whole environment.

It demonstrates the part of AI development that sits beyond prompting: information architecture, hybrid search, ranking, lifecycle policy, provenance, and honest evaluation of what recall has and has not been proven.
