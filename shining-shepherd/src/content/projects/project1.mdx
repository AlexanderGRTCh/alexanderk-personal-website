## Security checks inside delivery

This project demonstrates a delivery pipeline for a small Python application. It places testing and security checks before infrastructure changes. The workflow can run against AWS or a local LocalStack environment.

## What I built

I packaged a Flask application in Docker and described its infrastructure with Terraform. GitHub Actions coordinates pytest, Bandit, Trivy, and Terraform steps. Bandit checks Python code, while Trivy checks repositories and container images. Configured failures can stop later workflow stages before deployment begins.

## Engineering approach

Terraform models EC2, S3, IAM, security groups, Secrets Manager, CloudTrail, and GuardDuty. LocalStack provides a local AWS simulation for development without provisioning paid cloud resources. Boto3 retrieves application secrets at runtime. A Python port checker verifies the expected network exposure after provisioning.

The workflow saves JSON reports and logs under <code>reports/</code>. These artifacts make each demonstration easier to inspect and repeat. A Terraform plan also exposes proposed infrastructure changes before an apply step.

Together, the components show where delivery controls produce useful evidence for repeatable engineering review.

## Result

The repository connects application code, container packaging, infrastructure, and security tooling. It demonstrates how automated evidence can support a more reviewable cloud delivery process. The project is an engineering demonstration, not a production customer deployment.
