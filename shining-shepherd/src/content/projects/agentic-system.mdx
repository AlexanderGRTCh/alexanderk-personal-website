## Keeping work moving across sessions

A useful assistant needs more than a good answer. It needs the right history, access to tools and a way to recover unfinished work.

I built this environment around the work of developing products and running Ktisis Arc. It supports Claude and Codex through shared rules, memory and tools. The active core runs on Windows. Its earlier Linux gateway informed the design.

## Follow one task

When I resume a product task, the system first finds its project context. It can retrieve previous decisions, use the relevant tools and divide bounded work between agents. Findings return for review before I accept the result.

I use this approach in work on [StreakUp](/projects/streakup-habit-tracker). It also supports recurring research, document preparation and operational checks. The useful outcome is continuity: less repeated explanation and a traceable record of the work.

## A measured improvement

The original workspace map loaded **8,316 text tokens**. The replacement root map loaded **773**, with topic indexes opened as needed. That reduced the root context by **90.7%** at the September 7 implementation snapshot.

A bounded lookup check exposed two routing weaknesses, which I corrected. Targeted checks then resolved them. This establishes a smaller starting context and working routes in those cases. It does not measure billing savings or prove equal recall across every task.

<details>
<summary>Engineering decisions</summary>

A shared boot protocol separates essential rules from optional project context. Current context is reused; missing sources are reported. The [Hippocampus memory layer](/projects/hippocampus) combines keyword and semantic retrieval in SQLite.

Tools are exposed through MCP and local scripts. Provider adapters keep vendor behavior separate from the shared workflow. Review can compare findings from different providers, while persisted run state supports recovery.

Bounded execution, duplicate checks and liveness monitoring help contain work. The system still needs an operator to resolve failures and approve consequential decisions. Earlier review records include token cost estimates, not independently billed savings.

</details>
